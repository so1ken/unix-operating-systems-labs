# Лабораторная работа № 4. Горизонтально масштабируемый сервис

## Идея проекта

Распределённый математический калькулятор. Пользователь отправляет математическое выражение HTTP-запросом. API передаёт задание в RabbitMQ и ожидает ответ. Один из запущенных Worker получает выражение, вычисляет результат и возвращает его API через временную очередь ответа.

## Архитектура

```text
                 HTTP POST /calculate
Пользователь ------------------------------> API
                                                |
                                                | задание
                                                v
                                          RabbitMQ
                                                |
                           +--------------------+--------------------+
                           |                    |                    |
                           v                    v                    v
                        Worker 1             Worker 2             Worker 3
                           |                    |                    |
                           +--------------------+--------------------+
                                                |
                                      результат через RabbitMQ
                                                |
                                                v
                                               API
                                                |
                                                v
                                           Пользователь
```

Контейнеры:

- `api` — HTTP-сервер на стандартной библиотеке Python. Принимает выражения и отправляет их в очередь.
- `rabbitmq` — брокер сообщений. Распределяет задания между потребителями.
- `worker` — вычислитель. Реплики запускаются из одного Docker-образа и конкурируют за сообщения общей очереди.

Горизонтальное масштабирование выполняется для `worker`. `basic_qos(prefetch_count=1)` не позволяет одному работнику заранее забрать много заданий, пока другие свободны. После обработки Worker подтверждает сообщение (`basic_ack`).

## Поддерживаемые операции

- `+` сложение;
- `-` вычитание;
- `*` умножение;
- `/` деление;
- `//` целочисленное деление;
- `%` остаток от деления;
- `**` возведение в степень;
- скобки и унарные `+` / `-`;
- целые и вещественные числа.

Вычислитель разбирает выражение через `ast` и разрешает только перечисленные арифметические узлы. Есть ограничения на длину и сложность выражения, величину результата и показатель степени.

## Запуск
Нужны Docker Desktop с включённой интеграцией WSL2 для используемого дистрибутива либо Docker Engine и Compose Plugin внутри Linux.

Перейдите в каталог `lab4` и выполните:

```bash
docker compose up --build -d --scale worker=3
```

Проверить контейнеры:

```bash
docker compose ps
```

В списке должны быть API, RabbitMQ и три контейнера Worker.

## Проверка API

Проверка состояния:

```bash
curl http://localhost:8000/health
```

Отправка выражения:

```bash
curl -X POST http://localhost:8000/calculate \
  -H 'Content-Type: application/json' \
  -d '{"expression":"2 + 3 * (10 - 4) ** 2"}'
```

Ожидаемый результат — `110`. В JSON-ответе также будет имя контейнера Worker, который выполнил вычисление.

Другие примеры:

```bash
curl -X POST http://localhost:8000/calculate -H 'Content-Type: application/json' -d '{"expression":"(25 + 5) / 3"}'
curl -X POST http://localhost:8000/calculate -H 'Content-Type: application/json' -d '{"expression":"2 ** 10"}'
curl -X POST http://localhost:8000/calculate -H 'Content-Type: application/json' -d '{"expression":"10 / 0"}'
```

Последний пример должен вернуть понятную ошибку деления на ноль.

## Демонстрация нескольких Worker

Отправить несколько запросов параллельно из Bash:

```bash
for i in $(seq 1 12); do
  curl -s -X POST http://localhost:8000/calculate \
    -H 'Content-Type: application/json' \
    -d "{\"expression\":\"$i * $i\"}" &
done
wait
```

Посмотреть, какие реплики обрабатывали задания:

```bash
docker compose logs --tail=100 worker
```

В логах будут имена Worker-контейнеров. Поскольку задания простые и быстро выполняются, в отдельном запуске не гарантируется, что каждый Worker обязательно получит хотя бы одно задание; при параллельной отправке запросов обычно хорошо видна работа нескольких реплик.

Увеличить число работников до пяти:

```bash
docker compose up -d --scale worker=5
```

## Остановка

Остановить контейнеры, сохранив данные RabbitMQ:

```bash
docker compose down
```

Остановить контейнеры и удалить том RabbitMQ:

```bash
docker compose down -v
```
